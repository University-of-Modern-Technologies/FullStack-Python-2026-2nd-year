
# Порядок роботи з міграціями

Ось стандартний цикл розробки при використанні Alembic.

## 1. Ініціалізація

Виконується один раз. Створює структуру папок та конфігураційний файл `alembic.ini`.

```bash
alembic init migrations
```

Примітка: після цього потрібно у файлі `env.py` вказати `target_metadata`, щоб Alembic бачив ваші моделі.

## 2. Створення міграції

Alembic порівнює стан ваших моделей у коді з поточною схемою БД і автоматично генерує скрипт.

```bash
alembic revision --autogenerate -m "опис змін"
```

## 3. Перевірка скрипта

Важливо: завжди переглядайте згенерований файл у папці `versions/`, оскільки `autogenerate` може не помітити зміну імені колонки або специфічні типи даних.

## 4. Застосування міграції

Оновлює базу даних до останньої версії.

```bash
alembic upgrade head
```

## 5. Відкат змін

Якщо потрібно повернутися на одну ревізію назад:

```bash
alembic downgrade -1
```

## Основні команди

| Команда | Опис |
| --- | --- |
| `alembic upgrade head` | Застосувати всі актуальні міграції до останньої версії. |
| `alembic revision --autogenerate` | Створити новий файл міграції на основі змін у моделях. |
| `alembic current` | Показати поточну версію (ревізію) бази даних. |
| `alembic history --verbose` | Вивести список усіх створених міграцій. |
| `alembic downgrade base` | Відкотити всі міграції (очистити схему до початкового стану). |
| `alembic check` | Перевірити, чи збігаються моделі з БД (корисно для CI/CD). |
